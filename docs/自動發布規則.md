# 自動發布 Firestore 安全性規則

設定一次之後,`firestore.rules` 改了推上 `main`,GitHub 就會自動幫你發布,
不用再去 Firebase 後台貼一次。

失敗的話會寄信給你(GitHub 預設會通知 workflow 失敗)。
**失敗 = 沒有發布**,線上跑的還是舊的那一份 —— 不會把壞掉的規則推上去。

---

## 設定(大約五分鐘,只要做一次)

### 0. 開啟 Firebase Rules API

開 <https://console.developers.google.com/apis/api/firebaserules.googleapis.com/overview?project=classroom-management-sys-26f97>
→ 按「**啟用**」。

> 平常在 Firebase 後台貼規則不需要這個 API,所以多數專案是關著的。
> 用程式發布才會用到。按一次就好,**不用付費、不用升級方案**。
> 啟用後要等一兩分鐘才會生效。

### 1. 建立一個服務帳戶

1. 開 <https://console.cloud.google.com/iam-admin/serviceaccounts?project=classroom-management-sys-26f97>
2. **先確認畫面最上方的專案選擇器顯示的是 `Classroom Management System`**
   (或 `classroom-management-sys-26f97`)。
   Google Cloud 的專案選擇器會記住你上次看的專案,有時會蓋掉網址裡的指定 ——
   建在別的專案底下的金鑰是不能用的,而且錯誤訊息只會給你一串看不懂的
   專案編號。流程裡已經加了檢查,一開始就會告訴你金鑰是哪個專案的。
3. 上方「**建立服務帳戶**」
4. 名稱填 `github-rules-deployer`(名字隨便,看得懂就好)→ 建立並繼續
5. 「授予這個服務帳戶專案存取權」的角色選 **Firebase Rules 管理員**
   (英文介面是 `Firebase Rules Admin`)→ 繼續 → 完成

> 只要這一個角色。它**只能改規則,碰不到你的資料**。
>
> (`firebase deploy` 發布前原本還會去問 Google「Firestore API 開了沒」,
> 那一步需要另一個權限。流程裡已經把那個檢查跳過了 —— 這個專案的
> Firestore 本來就開著,網站天天在用 —— 所以不必再多給一個角色。)

### 2. 下載金鑰

1. 在服務帳戶列表點剛建立的那一個
2. 上方「**金鑰**」分頁 → 新增金鑰 → 建立新的金鑰 → 選 **JSON** → 建立
3. 瀏覽器會下載一個 `.json` 檔。**用記事本打開,整份內容複製起來**

### 3. 貼進 GitHub

1. 開 <https://github.com/znxuyz/class/settings/secrets/actions>
2. 「**New repository secret**」
3. Name 填:`FIREBASE_SERVICE_ACCOUNT`
4. Secret 貼上剛剛那整份 JSON(含最外層的大括號)
5. Add secret

> 這個 secret GitHub 不會顯示給任何人看,也不會出現在流程的畫面上。
> 貼完之後把下載的那個 `.json` 檔刪掉。

### 4. 測一次

開 <https://github.com/znxuyz/class/actions> → 左邊點「發布 Firestore 規則」
→ 右邊「**Run workflow**」→ 綠色打勾就成功了。

---

## 之後怎麼用

什麼都不用做。規則改了、推上 `main`,它就會自己跑。

想手動跑一次(例如想確認線上的規則是不是最新的),一樣去 Actions 頁面按
「Run workflow」。

---

## 出問題的時候

| 畫面上的訊息 | 原因與處理 |
| --- | --- |
| `找不到 FIREBASE_SERVICE_ACCOUNT` | 第 3 步沒做,或名字打錯 |
| `金鑰屬於專案「X」,但要發布的是「Y」` | 服務帳戶建錯專案了。在正確的專案底下重建一次 |
| `Firebase Rules API has not been used in project` + 一串**不是** `584347256149` 的編號 | 同上 —— 那是金鑰所屬專案的編號,不是這個專案 |
| `Firebase Rules API has not been used in project` + `584347256149` | 第 0 步沒做,或剛啟用還沒生效。等一兩分鐘重跑 |
| 提到 `serviceusage` 的 403 | 「跳過 API 啟用檢查」那一步沒生效,確認 `.firebaserc` 的專案代號對不對 |
| 其他 `Permission denied` / `403` | 少了 **Firebase Rules 管理員**。補角色就好,金鑰不用重做 |
| `Error parsing rules` 之類 | 規則本身有語法錯誤。**這是好事** —— 它幫你擋下來了,線上還是舊的那份 |

## 這份設定包含哪些檔案

| 檔案 | 用途 |
| --- | --- |
| `.github/workflows/deploy-rules.yml` | 自動發布的流程 |
| `firebase.json` | 告訴 firebase 指令「規則在 `firestore.rules`」 |
| `.firebaserc` | 專案代號 `classroom-management-sys-26f97` |

刻意**只發布規則**(`--only firestore:rules`),不碰索引、不碰資料、
不碰 Hosting —— 網站本身還是 GitHub Pages 在跑,這個流程動不到它。
