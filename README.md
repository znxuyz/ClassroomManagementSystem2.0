# 守護獸學園 · 班級養成系統

一個為國小教師設計的「**遊戲化班級經營**」工具,把傳統的加分制升級為**虛擬寵物養成系統**——學生每次表現好,可以餵養自己的台灣特有種守護獸,從蛋孵化成神獸。

> 為什麼是台灣特有種?因為它們本身就是教材。每個孩子養著的是真實存在的、瀕危的、需要被認識的這片土地的居民。

## ✨ 為什麼自己做?

過去要做這樣的系統,要學 HTML、CSS、JavaScript、資料庫、後端伺服器,**至少半年起跳**。所以老師只能用現成的、忍受三個限制:

- **免費版的天花板**:學生數受限、進階功能要付費
- **無法客製化**:寵物就是那幾隻、規則就是那幾條
- **資料不是你的**:存在別人的伺服器,服務收掉就消失

這個專案示範的不只是一個系統,而是「**AI 時代,老師也可以是工具創造者**」這件事。

## 🎯 系統功能總覽

**核心:守護獸養成**

8 種台灣特有種(台灣黑熊、石虎、櫻花鉤吻鮭、帝雉、台灣藍鵲、穿山甲、山羌、台灣獼猴)各 4 個成長階段(蛋 → 幼獸 → 成獸 → 守護神獸)。

積分雙軌制:**累積經驗**(寵物進化用,只增不減) vs **可用積分**(商店消費用)。

健康機制:超過 3 天沒被關注的學生,寵物會「微恙」;超過 7 天會「生病」。系統會自動把這些孩子列入「需要關心」清單。

**老師端**(頂端八個大分類,每一類底下再分子頁)

| 分類 | 底下有什麼 |
|---|---|
| 聯絡簿 | 今日自動匯整、作業繳交追蹤、AI 訊息潤飾 |
| 班級管理 | 學生加分、點名出席、座位表、隨機分組、抽籤機、計時器、積分規則 |
| 兌換商店 | 獎品管理(含技能果實)、兌換申請、班級共同任務 |
| 學習挑戰 | 學生測驗、蜂巢戰紀(戰況地圖 + 題庫)、**積木冒險** |
| 數據成果 | 班級概況、排行榜、學期成長報表、投影模式、AI 評語與行為分析 |
| 學生模擬 | **在自己的畫面裡看「這位學生登入會看到什麼」**(手機 / 平板 / 電腦三種寬度) |
| 使用說明 | 教師端 / 學生端的完整說明,內容直接從程式產生,不會和實際行為脫節 |
| 系統設定 | 班級與學生、遊戲設定(技能、出席分…)、資料與備份、外觀與 AI |

**學生端**(雲端模式,Google 登入後直接進入)

上排五個大分類:守護獸 / 排行榜 / **挑戰** / 兌換 / 說明;
測驗、蜂巢戰紀、積木冒險收在「挑戰」底下,分類上的數字是三項未完成的總和。

| 分頁 | 功能 |
|---|---|
| 守護獸 | 自己挑選物種、進化階段、雙軌積分、這禮拜的得分長條、**守護獸技能** |
| 排行榜 | 前三名頒獎台 + 自己名次;有分組時另有小組榜;有人拿過星星時另有星星榜 |
| 挑戰 · 測驗 | 作答,老師結算後看得到每一題的 ✓ ✗(但看不到正確答案) |
| 挑戰 · 蜂巢戰紀 | 分組後才出現,答題搶格子 |
| 挑戰 · 積木冒險 | micro:bit 積木關卡,做出功能就過關 |
| 兌換 | 用**可用積分或星星**換老師開的獎品與技能果實 |

**線上測驗的兩種計分模式**

- **答對就得分**:每個答對的人都拿到分數,適合個人作業與隨堂練習
- **逐題搶答:每題前 N 名得分**:課堂搶答用。學生一題一題往下答,每一題各自比快 ——
  第 1 題最快答對的前 N 位得分,第 2 題重新比一次。一題一份作答文件、只能建立不能修改,
  時間戳由伺服器蓋,所以順序偽造不了,同一題也只能答一次。
- **整份測驗前 N 名得分**:先比答對總題數,同分時先交卷的在前,取前 N 名。

先後順序一律由 Firestore 的伺服器時間戳決定,不看學生裝置的時鐘,
所以同時大量答對也不會亂序或重複給分。

還可以設定**統一結算時間**(日期 + 24 小時制的時間,例如今晚 00:00):時間到之前只記錄交卷順序,
畫面上只顯示「已交卷」;時間一到,老師開啟系統就一次批改、一次排名次、一次發分。
搶答不必邊收邊算,名次也不會因為分批結算而變動。

成績公布後,學生看得到自己答對幾題、名次,以及每一題的 ✓ / ✗ —— 但看不到正確答案。

**蜂巢戰紀**(分組後才能玩,舊名「領地佔領戰」)

蜂窩狀大地圖,各組從自己的基地往外答題擴張。

- **題目與答案老師事先設定好**,誰先答對、誰佔到格子完全由系統判定,老師不必當裁判
- **難度決定佔領分**,格子要累積到門檻才易主;別組的格子也能打,設定時間內誰積分高誰拿走
- **8 種地圖形狀**(六角、矩形、環、十字、星、群島、洞窟、世界地圖)× 5 種尺寸,
  最大 2000 格以上,夠打一整個學年
- **階段性開放**:從各組初始領地往外一圈一圈開放,也可以由老師框選多個格子手動開放/封鎖
- 地圖本身不存檔,而是由作答事件依伺服器時間**重播**還原,所以每台裝置看到的戰況一致。
  事件累積到一定量時,狀態列會出現「壓縮戰況」把目前局面存成快照。
- **開放時段**可以設(例如 08:00–16:00,也能跨夜)。時段外孩子看得到地圖與戰況、
  但按不了攻擊 —— 看得到他才會先想好等一下要打哪一格。

**積木冒險**(micro:bit 積木練習)

教 micro:bit 時最卡的一關不是「認不認得積木」,而是**拼不起來**。這個模式就是給那一關練的:

- 老師出的是一段**功能敘述**(「開機步數歸零並顯示,晃一下加一,A+B 歸零」),
  學生在一個**和 MakeCode 長得一樣**的編輯器裡把積木拼出來
- **判的是跑出來的結果,不是拼法**。系統把程式真的跑一遍,比對螢幕、廣播、聲音 ——
  用 while 取代重複幾次、變數取別的名字、把 else-if 拆成三個 if,只要做出一樣的結果都算對
- 題目排成一條**關卡地圖**,每關最多三顆星(做出來了 / 沒用提示 / 積木夠精簡)
- 題目可以**從 MakeCode 直接匯入**:把 `.hex` 檔拖進來,或把 JavaScript 貼上,
  參考解答就自動拼好了。還能一次加到好幾個班
- 用到廣播時模擬器會變成**兩台 micro:bit** —— 一台收不到自己發出去的廣播
- 老師端有**全班進度牆**可以投影:每個人的守護獸停在他走到的那一關

**守護獸技能**(預設關閉,在「系統設定 → 遊戲設定」開)

學生用積分或星星在商店買「技能果實」,一個技能買一次就永久擁有;
**守護獸每進化一階,同一個技能就更強** —— 所以進化不只是外觀變化。

技能照「在哪裡用得到」分區:蜂巢戰紀(猛擊 / 護盾 / 靜心 / 巧手 / 加時 / 夜襲)、
測驗(專注 / 保險 / 送分 / 刪去 / 重來)、積木冒險(偵錯 / 工具箱 / 開路 / 放大鏡)、
守護獸(成長)、商店(議價)。

三條底線:**次數每週一歸零**(強技能不會讓差距滾雪球)、
**每次使用都在伺服器留一筆不可改的紀錄**(改前端沒有用)、
**技能只加成自己,不會傷害別人**(小學班級裡能互相扣分的機制只會製造糾紛)。

**兩種錢**

積木冒險拿到的**星星**也能在商店當錢用。老師在獎品上填「星星價」就收星星,
兩種價錢都填就兩種都收(學生自己選)。

星星**換不到積分**,也沒有兌換率 —— 有兌換率的話,孩子就會為了第三顆星
去刪掉看得懂的積木。星星榜排的是「累積拿到幾顆」,所以花掉星星不會掉名次。

## 🚀 快速開始

### 老師(使用者)

1. **下載整個專案**:點 GitHub 右上 `Code` → `Download ZIP`
2. **解壓縮到任意位置**(例如桌面、隨身碟)
3. **雙擊 `index.html`**——用 Chrome 或 Edge 開啟
4. 首次使用會看到設定畫面,輸入班級名稱、老師稱呼,然後:
   - 直接點「載入示範資料」看完整功能 demo
   - 或從 `assets/學生資料範本.xlsx` 編輯後匯入自己班級
   - 或手動輸入學生名單

5. **存到隨身碟、雲端硬碟、或學校電腦桌面**都可以,完全離線運作

### 老師(進階:讓 AI 幫你)

申請 Anthropic API Key:

1. 至 [console.anthropic.com](https://console.anthropic.com) 註冊
2. 充值 USD $5(約 NT$160,可使用很久)
3. 建立 API Key 並複製
4. 在系統的「**設定**」→ AI 助手區塊貼上 Key 並儲存

然後就能用三個 AI 功能:**評語生成 / 家長訊息潤飾 / 行為觀察分析**。每次使用約 NT$0.1-0.5 元。

### 怎麼修改

想改某個功能?直接打開對應的檔案,**不用碰其他檔案**。

| 想改什麼 | 改哪個檔案 |
|---|---|
| 換守護獸物種 | `js/01-constants.js` 的 `PET_SPECIES` |
| 改進化所需的積分 | `js/01-constants.js` 的 `STAGE_THRESHOLDS` |
| 改技能的效果或價錢 | `js/skills/01-defs.js` 的 `PET_SKILLS`(四階效果表、說明都從這裡產生) |
| 新增一塊積木 | `js/blocks/01-defs.js` 加定義 + `02-vm.js` 加執行 |
| 改蜂巢地圖形狀/尺寸 | `js/territory/02-shapes.js` 的 `MAP_SHAPES` / `MAP_SIZES` |
| 改題目難度對應的佔領分 | `js/territory/03-engine.js` 的 `DIFFICULTY` |
| 新增/修改預設獎品 | `js/feature-shop.js` 的 `STARTER_SHOP_ITEMS`(平常直接在商店頁編輯就好) |
| 改顏色主題 | `css/base.css` 的 `:root` 變數 |
| 換 AI 模型 / API 設定 | `js/06-ai.js` |

## ✅ 自動化測試

```
bash tests/run.sh          # 全部(約三分鐘)
bash tests/run.sh 24       # 只跑編號 24 開頭的那一套
```

**36 套、720 多項**,用 Playwright 真的開起來點。測的不是函式回傳值,
是「老師真的會做的那個動作,做完之後畫面與資料對不對」—— 例如:

- 重複點兩次「發放出席分」不會加兩次分

- 25 個頁面 × 3 種寬度都畫得出來、沒有水平溢出
- 文字對比度符合 WCAG AA
- 從 MakeCode 匯入老師真的下載的那個 `.hex`,換一種寫法也判得過

改完 UI 之前先讀 `.claude/skills/ui-design/SKILL.md`(這個專案的版面與視覺規範),
改完照著最後那張檢查清單跑一次。

## 🎨 自製寵物圖片(讓系統更有質感)

預設使用 emoji 顯示寵物(🐻 🐱 🐟...),適合先快速開始用。如果想做出有品味的版本,有兩個做法:

**做法 A:放自己的圖**

把 PNG 存到 `assets/pets/`,命名為 `{物種id}-{stage}.png`,例如 `bear-egg.png`、`bear-baby.png`、`bear-adult.png`、`bear-guardian.png`。完整的 32 個檔名列在 `assets/pets/README.md`。

**不用改程式**。系統會自動去找圖,找不到就退回 emoji,所以可以一次只上傳幾張,沒上傳的維持原樣。建議去背存成透明 PNG。

**做法 B:用 emoji 但換主題**

例如要做寶可夢版本,只要改 `01-constants.js`:

```js
const PET_SPECIES = [
  { id: 'pika', name: '皮卡丘', icon: '⚡', desc: '電氣鼠寶可夢' },
  ...
];
```

## 🤖 AI 功能說明

需要自備 Anthropic API Key。三個功能:

**評語生成** — 輸入學生 + 觀察關鍵字 → 系統自動帶入該生的寵物狀態、近兩週積分、主要得分理由給 AI → 產出三種風格的評語草稿(溫暖具體 / 著重成長 / 精簡專業)。

**訊息潤飾** — 老師打草稿(可以很急很口語) + 選擇收件對象與情境 → AI 修飾成可直接寄出的版本,提供三種語氣(溫和 / 中性 / 堅定)。

**行為觀察分析** — 選學生 → 系統自動把這位學生完整的積分歷史、出席、作業繳交、商店消費等資料丟給 AI → 產出四段分析(模式 / 成因假設 / 警訊 / 建議行動)。**這是傳統工具完全做不到的——AI 看到的是時間累積的真實行為資料**。

| | 單機模式 | 雲端模式 |

| 學生登入 | 不支援 | Google 帳號,登入後直接進入自己的班級 |
| 線上測驗 | 不支援 | 支援,答對自動加分 |
| 排行榜 / 商店兌換 / 蜂巢戰紀 | 不支援 | 支援 |
| 積木冒險 / 守護獸技能 | 不支援(老師端可以先出題) | 支援 |
| 學生模擬 | 支援(看得到畫面,資料是本機的) | 支援 |
| 費用 | 免費 | 免費(在 Firebase 免費額度內) |

設定方式見 **[docs/雲端設定指南.md](docs/雲端設定指南.md)**,約 20 分鐘。

**老師身分只能在 Firebase Console 指定**(把 `users/{uid}` 的 `role` 改成 `teacher`),
系統裡沒有「我是老師」的選項 —— 否則任何人用 Google 登入都能建班級。
學生登入後若不在任何名冊,只會看到「請把信箱給老師」的畫面。

**30 位學生同時操作為什麼不會亂?**

關鍵在**寫入權責分離**:班級資料只有導師寫得動,學生只能寫「自己那一份」文件
(作答、兌換、選守護獸、領地事件,文件 id 都綁定學生帳號 uid)。
因此再多人同時操作,寫入的位置本來就不同,物理上不可能互相覆蓋。

排序一律用 Firestore 的 `serverTimestamp()`,不信任學生裝置的時鐘,搶答才會公平。

發布給學生的題目不含正確答案;領地戰的答案另存一份學生讀不到的文件,
由 `firestore.rules` 在伺服器端比對後才准許寫入,所以老師不用開著電腦當裁判。
所有權限都是規則強制執行,不是靠前端擋。

## 🔧 技術細節

- 純前端網頁,**單機模式無需後端伺服器**
- 單機模式資料存 localStorage;雲端模式存 Firestore,localStorage 當離線快取
- 使用 [SheetJS](https://sheetjs.com) 解析 Excel
- 字型使用 Google Fonts 的 Noto Serif TC + Noto Sans TC
- Firebase 用 compat SDK 以 `<script>` 載入,**沒有 build 步驟**
- 蜂巢地圖用固定亂數種子(mulberry32)產生,所以同一個班在每台裝置上看到的地形一致
- 積木冒險自己寫了一台小直譯器(假時鐘 + 可重現的亂數 + 步數上限,
  所以無限迴圈會被抓出來而不是把分頁卡死);判題比的是**跑出來的行為**
- `.hex` 裡的專案原始碼是 LZMA 壓縮的,解壓縮器也是自己寫的
  (`js/blocks/11-lzma.js`)—— 為了一個檔案掛一個 CDN 相依,
  等於把「老師打不開系統」的風險接進來
- 介紹影片用 Playwright 錄真的程式、ffmpeg 合成、配樂用 numpy 合成

### 為什麼是「無框架」?

刻意不使用 React/Vue 等框架,因為:
1. 老師想客製化時不用學現代前端工具
2. 沒有 build 步驟,純 HTML 雙擊即可開啟
3. 程式碼可讀性高,適合作為教學範例
4. 體積小,網路慢也能用
