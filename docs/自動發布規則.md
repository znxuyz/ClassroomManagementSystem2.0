# 自動發布 Firestore 安全性規則

設定一次之後,`firestore.rules` 改了推上 `main`,GitHub 就會自動幫你發布,
不用再去 Firebase 後台貼一次。

失敗的話會寄信給你(GitHub 預設會通知 workflow 失敗)。
**失敗 = 沒有發布**,線上跑的還是舊的那一份 —— 不會把壞掉的規則推上去。

---

## 設定(大約五分鐘,只要做一次)

### 1. 拿一把金鑰

有兩條路,**先用 A**。A 不會建錯專案,也不必自己挑角色。

#### A. 從 Firebase 後台拿(建議)

1. 開 <https://console.firebase.google.com/project/classroom-management-sys-26f97/settings/serviceaccounts/adminsdk>
2. 下方「**產生新的私密金鑰**」→ 確認 → 瀏覽器會下載一個 `.json`

> 這把金鑰**一定屬於這個專案**(從專案設定裡產生的),所以不會發生
> 「建錯專案」那種問題 —— 那是前幾次卡住的真正原因。
>
> 代價:它的權限比較大(Firebase 管理用的帳戶,資料也碰得到),
> 不像 B 那樣只能改規則。它只放在 GitHub 的 secret 裡、只有這個
> 發布流程用得到,所以可以接受;但如果你想要最小權限,就走 B。

#### B. 自己建一個只能改規則的服務帳戶(最小權限)

1. 開 <https://console.cloud.google.com/iam-admin/serviceaccounts?project=classroom-management-sys-26f97>
2. **先確認畫面最上方的專案選擇器顯示的是 `Classroom Management System`**。
   Google Cloud 的專案選擇器會記住你上次看的專案,有時會蓋掉網址裡的指定 ——
   建在別的專案底下的金鑰是不能用的。
   (流程裡已經加了檢查,金鑰不對會直接告訴你它是哪個專案的。)
3. 上方「**建立服務帳戶**」→ 名稱填 `github-rules-deployer` → 建立並繼續
4. 角色選 **Firebase Rules 管理員**(`Firebase Rules Admin`)→ 繼續 → 完成
5. 點進剛建好的帳戶 →「**金鑰**」分頁 → 新增金鑰 → 建立新的金鑰 → **JSON**

> 這條路只能改規則,碰不到你的資料。
>
> 另外需要確認 **Firebase Rules API** 在專案裡是啟用的:
> <https://console.developers.google.com/apis/api/firebaserules.googleapis.com/overview?project=classroom-management-sys-26f97>
> (走 A 的話通常本來就開著,不用管。)

### 2. 貼進 GitHub

1. 開 <https://github.com/znxuyz/ClassroomManagementSystem2.0/settings/secrets/actions>
2. 「**New repository secret**」
3. Name 填:`FIREBASE_SERVICE_ACCOUNT`
4. Secret 貼上剛剛那整份 JSON(含最外層的大括號)
5. Add secret

> 這個 secret GitHub 不會顯示給任何人看,也不會出現在流程的畫面上。
> 貼完之後把下載的那個 `.json` 檔刪掉。

### 3. 測一次

開 <https://github.com/znxuyz/ClassroomManagementSystem2.0/actions> → 左邊點「發布 Firestore 規則」
→ 右邊「**Run workflow**」→ 綠色打勾就成功了。

---

## 之後怎麼用

什麼都不用做。規則改了、推上 `main`,它就會自己跑。

想手動跑一次(例如想確認線上的規則是不是最新的),一樣去 Actions 頁面按
「Run workflow」。

---

## 出問題的時候

| 畫面上的訊息 | 原因與處理 |
| --- | --- |
| `找不到 FIREBASE_SERVICE_ACCOUNT` | 第 2 步沒做,或名字打錯 |
| `金鑰屬於專案「X」,但要發布的是「Y」` | 金鑰建錯專案了。改走上面的 **A**,它不會建錯 |
| `Firebase Rules API has not been used in project` + 一串**不是** `584347256149` 的編號 | 同上 —— 那是金鑰所屬專案的編號,不是這個專案 |
| `Firebase Rules API has not been used in project` + `584347256149` | 第 0 步沒做,或剛啟用還沒生效。等一兩分鐘重跑 |
| 提到 `serviceusage` 的 403 | 「跳過 API 啟用檢查」那一步沒生效,確認 `.firebaserc` 的專案代號對不對 |
| 其他 `Permission denied` / `403` | 走 B 的話是少了 **Firebase Rules 管理員**。補角色就好,金鑰不用重做 |
| Google Cloud 主控台顯示「無法載入,請再試一次」 | 主控台自己的載入問題,跟專案無關。按重試,或用無痕視窗(擋廣告的套件常弄壞它) |
| `Error parsing rules` 之類 | 規則本身有語法錯誤。**這是好事** —— 它幫你擋下來了,線上還是舊的那份 |

## 這份設定包含哪些檔案

| 檔案 | 用途 |
| --- | --- |
| `.github/workflows/deploy-rules.yml` | 自動發布的流程 |
| `firebase.json` | 告訴 firebase 指令「規則在 `firestore.rules`」 |
| `.firebaserc` | 專案代號 `classroom-management-sys-26f97` |

刻意**只發布規則**(`--only firestore:rules`),不碰索引、不碰資料、
不碰 Hosting —— 網站本身還是 GitHub Pages 在跑,這個流程動不到它。
