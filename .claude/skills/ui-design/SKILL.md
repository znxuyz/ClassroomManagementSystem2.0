# 守護獸學園 · 版面與視覺規範

這個專案是**正在上課的五個班（601–605，約 143 位學生）在用的系統**，
老師在投影機前一天按幾十次。所以版面的目標不是好看，是：

> **一眼看得完、按得準、印得出來、色弱也讀得懂。**

這一份是從實際踩過的坑長出來的。每一條後面都附了「為什麼」——
沒有理由的規則會被下一個人當成品味問題改掉。

---

## 0. 先跑測試，再動手

改版面之前先知道有哪些事已經被釘住了：

```bash
bash tests/run.sh          # 全部（22 套，約一兩分鐘）
bash tests/run.sh 01       # 只跑版面那一套
bash tools/check-css-vars.sh
```

和版面直接相關的幾套：

| 套 | 釘住的事 |
|---|---|
| `01-layout` | 25 個頁面 × 3 種寬度都沒有水平溢出 |
| `10-dashboard` | 學生加分方格一眼看得完、手機四欄、卡片不被壓縮 |
| `12-visual-system` | 圓角/間距/字級都用 token，沒有散落的硬寫值 |
| `13-contrast` | 兩種主題的文字對比都過 WCAG AA |
| `14-keyboard` | Enter 送出、Esc 收起、注音選字不會誤送 |
| `16-interaction` | 每一個可點的東西滑過去都有反應 |
| `22-projector` | 投影時全班都在一個畫面裡(三種解析度 × 三種班級人數) |
| `21-grid-rows` | **同一排的格子一樣高** |

**改完一定要再跑一次。** 新增規則時優先「加一條測試」而不是「寫在這份文件裡」——
文件會被忘記，測試不會。

## 1. 進階設計邏輯：讓畫面「好看」的那幾件事

好看不是加裝飾，是**把同一件事講得更清楚**。下面每一條都可以對著畫面驗證，
不是品味問題。

### 1.1 一個畫面只有一個主角

每一頁先問「老師／學生打開這一頁，眼睛第一個該落在哪裡？」，
然後讓**只有那一個**最大、最重、最有顏色，其他全部退一階。

- 學生加分頁的主角是**學生的守護獸方格**，所以守護獸 64px、階段用外圈光暈、
  階段名稱整個拿掉（28 列重複寫「守護神獸」是純粹的雜訊）。
- 學生端守護獸頁的主角是**那隻獸**，所以牠置中放大，數字在牠下面。
- 一個畫面出現兩個主角，等於沒有主角 —— 那是「版面很滿但看不懂」的來源。

### 1.2 層次來自對比，不是來自框線

要讓 A 比 B 重要，**四個工具依序試**：大小 → 字重 → 顏色深淺 → 周圍的留白。
加一條框線、加一個底色、加一個陰影，是最後手段。

> 判斷法：把畫面**瞇起眼睛**看（或縮到 25%）。該先看到的東西有先浮出來嗎？
> 如果整片一樣灰，問題不是「不夠漂亮」，是層次沒做出來。

### 1.3 留白屬於群組，不屬於元素

同一組的東西靠近、不同組的東西拉開。**組內的間距一定要小於組外**，
不然眼睛分不出哪幾樣是一夥的。

- 間距用 4 的倍數（6／8／10／14／20／28），不要出現 7px、13px 這種值。
- 一個區塊「上面的空白」要大於「裡面的空白」。
- 這比任何裝飾都有效：版面看起來亂，九成是間距沒有節奏，不是顏色不好看。

### 1.4 巢狀的圓角要算過

卡片裡面再放一張卡片時，**內圓角 = 外圓角 − 兩者之間的內距**。
外 12px、內距 8px → 內圓角 4px。直接也用 12px 的話，兩個弧不同心，
看起來會「鼓鼓的」。這個專案的 `--r-card 12 / --r-tile 8` 就是照這個關係訂的。

### 1.5 高度是物理，不是裝飾

陰影的意思是「這個東西離紙多遠」，不是「這裡要漂亮一點」。

- 真實的陰影是**兩層**：很短很淡的接觸影（把它黏在紙上）+ 大而散的環境影
  （表示高度）。只用一層，淡了像沒有、濃了像貼紙。
- 光從上面來：`y` 永遠是正的；離得越遠，模糊越大、透明度越低。
- 影子帶一點底色的色相（這裡是 `--ink` 的暖褐），純黑會發灰。
- 浮起來的表面上緣補一道極淡的亮線（`--edge-hi`）—— 看不出來，但拿掉會扁掉。
- **高度要有意義**：貼在紙上的 `sm`、浮起來的 `md`、蓋住全部的 `lg`，就這三階。
  卡片 hover 時從 `sm` 換到 `md`，而且**位移與陰影要一起動** ——
  只動其中一個會像「圖片在滑」而不是「卡片被拿起來」。

### 1.6 動態要分級，而且要解釋來源

- `--dur-fast 120ms`　指下去就要有反應的（hover、按下去）
- `--dur 200ms`　　　 介面自己的變化（展開、切換、滑動高亮）
- `--dur-slow 500ms`　資料的變化（長條成長、進度條）

同一種動作一律用同一個時間，整個介面才像同一個人做的。
動畫要**解釋東西從哪裡來**（浮層從下面滑上來、下拉從觸發點展開），
不解釋任何事的動畫就是噪音。超過 500ms 的轉場一律是錯的。
`prefers-reduced-motion` 要關掉動畫（base.css 已經有）。

### 1.7 圖示是一套系統，不是一堆符號

- **同一個格子（24×24）、同一個線寬（1.6）、同樣的圓端點、`currentColor`。**
  線寬不跟著尺寸放大 —— 放大的話大圖示變粗、小圖示變細，整排就不齊。
- **不要在介面裡混 emoji 與線性圖示。** 彩色的那一顆永遠比旁邊的重，
  視線會被它拉走；而且 emoji 在不同系統長得不一樣，字型裡沒有的還會變方框
  （這個專案的 `⚔` 就出過這件事）。
- 分界很清楚：**介面用畫的（`js/10c-icons.js`）、內容用 emoji** ——
  獎品圖示、守護獸、技能果實是老師與孩子挑的內容，那些留著。

### 1.8 字級只用訂好的那幾階

```
介面文字  10 / 11 / 12 / 13 / 14 / 16 / 18
標題      20 / 22 / 24 / 26 / 28 / 32 以上
```

比例大約 1.15–1.2。**半階一律不留** —— 相鄰兩階差太小(15 和 16、13 和 13.5)
的時候,讀者分不出那是「不同層級」還是「做壞了」。
以前散在各處的 9／10.5／11.5／12.5／13.5／14.5／15／17／21 都收攏掉了,
`tests/12-visual-system.mjs` 會擋住新的半階。

一次性的巨大數字(計時器 200px、投影的分數、守護獸大圖)不在此限 ——
那些是圖,不是文字。

### 1.9 給牆看的畫面和給桌看的畫面不一樣

投影模式是**全班一起看著的那一面牆**,規則和其他頁相反:

- **一個畫面要放得下全班**,因為投影時沒有人會去捲動。
  欄數由「人數 × 畫面比例」算出來(`projectorColumns()`),
  格子用 `1fr` 自己縮放;同時把「最後一排會空掉幾格」算進去 ——
  28 位排成 9 欄時最後一排只站一個孩子,看起來像漏掉了。
- **字級跟著畫面高度走(vh)**,不是寫死的 px:教室後排要看得到。
- **框線與底色拿掉**。28 個卡片框等於 28 個互相競爭的框;
  框只在加分的那一瞬間亮起來。
- **資訊減到最少**:守護獸、名字、分數。暱稱、階段名稱都拿掉 ——
  牆上每多一行字,獸就小一圈。

### 1.10 數字的排版有兩種

- 表格、排行榜、軸標籤 → `font-variant-numeric: tabular-nums`（等寬，不會跳動）
- 大的單一數字（英雄數字、統計卡）→ **比例字寬**，等寬會讓 `121` 看起來鬆鬆的

### 1.11 顏色只做四件工作

身分（categorical）、大小（sequential）、正負（diverging）、狀態（status）。
**不做裝飾。** 一個顏色出現在畫面上，要答得出它在做哪一件工作；
答不出來就拿掉。狀態色（好／注意／嚴重）是保留字，不能拿去當「第四個系列」。

### 1.12 克制

> 精準感來自克制，不是來自特效。（這句話寫在 `theme-aurora.css` 的開頭）

- 加東西之前先問「能不能靠拿掉別的東西達到同樣的效果」。
- 每多一條框線、一個底色、一層陰影、一個字級，都要說得出它解決了什麼。
- 同一個畫面裡，框線／底色／陰影**三選一**來分隔區塊，不要三個一起上。

### 1.13 怎麼驗證「真的變好看了」

1. **瞇眼測試** —— 縮到 25%，該先看到的有先浮出來嗎？
2. **灰階測試** —— 整頁轉成灰階，還分得出層次與正負嗎？（色弱的人看到的接近這樣）
3. **一件事測試** —— 這一頁在講一件事，說得出是哪一件嗎？
4. **去掉測試** —— 拿掉最花的那一個裝飾，有變難用嗎？沒有的話就不要加回去。

## 2. 設計 token：不要寫死任何數值

全部定義在 `css/base.css` 的 `:root`，深色主題在 `css/theme-aurora.css` 覆寫。

```
顏色   --forest-deep/--forest/--forest-light/--moss   森林綠系
       --paper/--paper-warm/--paper-shadow            紙色系（底、次底、分隔線）
       --ink/--ink-soft/--ink-muted                   文字三層
       --gold/--gold-ink/--sunset/--plum/--sky        強調色
       --healthy/--mild/--sick                        守護獸健康狀態
       --*-deep / --*-ink                             「白字的底」與「當文字」的加深版
       --data-pos / --data-neg                        圖表的增加／減少兩極

高度   --shadow-sm/md/lg（兩層:接觸影 + 環境影)、--edge-hi(上緣亮線)
動態   --dur-fast 120ms / --dur 200ms / --dur-slow 500ms、--ease-out

圓角   --r-card 12px（面板、卡片、對話框）
       --r-tile  8px（列、磚、按鈕大小的方塊，和 --control-r 同值）
       --r-pill 999px（標籤、徽章）

內距   --pad-sm 14px（工具列、密集小卡）
       --pad    20px（一般面板）
       --pad-lg 28px（對話框、英雄區）

字級   --t-section 16px（區塊標題）
       --t-item    15px（一張卡片代表的那個東西）
       --t-sub     13px（副標與說明）

控制項 --control-h 38px / -sm 30px / -lg 48px、--control-px、--control-r
```

規則：

- **不要在 CSS 或 JS 字串裡寫死色碼。** `tools/check-css-vars.sh` 會掃 `css/` 和 `js/`
  兩邊；曾經有一個紅色漸層寫在 JS 的 inline style 裡躲過檢查，直到有人讀圖表才發現。
- **一行裡的控制項一律用 `--control-h`。** 日期欄與下拉的「天然高度」比文字框高幾 px，
  不寫死就會高高低低。
- **白字配色要用 `-deep` 版。** `--moss` 3.47、`--mild` 2.95、`--sunset` 3.81 ——
  當文字或邊框沒問題，當「底色 + 白字」全部不夠。
- 深色主題不是自動翻轉，是另外選過的一組值（見 `theme-aurora.css`）。

## 3. 版面：三個會重複犯的錯

### 3.1 同一排的格子要一樣高

**已經發生過**：「5 天沒加分」的標籤只掛在部分學生身上，有標籤的卡片比較高，
整排格子被它撐開 —— 第一排 172px、第二排 153px，同一排的名字與分數對不齊。

做法：

- 有的有、有的沒有的東西，**要嘛永遠留著那一行的高度，要嘛放進本來就有的位置**。
  那次的修法是把天數寫進頭像右上角原本就有的小圓點（`::after` 讀 `data-quiet`），
  一點高度都不佔。
- 多開一行文字的代價不只是對不齊：1024 的螢幕上 28 位就會多出一排、
  不再「一眼看得完」（`10-dashboard` 會抓到）。
- 窄螢幕一行塞不下兩顆標籤 → **一張卡片最多一顆**，並訂出優先順序。
- `tests/21-grid-rows.mjs` 會掃過每一頁每一個格子容器驗這件事。

### 3.2 flex 子項的 `min-width: 0`

flex 子項預設**不准縮到比內容小**（`min-width: auto`）。這個坑在這個專案踩過四次以上：
原因欄把按鈕擠出面板外、輸入框在 768px 溢出、計時器那一排在 390px 爆開。

> 只要一個 flex 子項裡面有「長度不可控的文字」（學生姓名、加分原因、獎品名稱），
> 就給它 `flex: 1 1 auto; min-width: 0;`。

### 3.3 會捲動的面板裡要寫 `flex-shrink: 0`

`overflow-y: auto` 的 flex 欄會把子項壓扁而不是讓它捲動。
`.dashboard.has-selection .action-panel > * { flex-shrink: 0; }` 就是為了這件事，
而且**手機與桌機要共用同一條**（只寫在手機的 media query 裡，桌機加上 `max-height` 之後又壞一次）。

### 其他

- 手機 390px：左右各留 16px，不能有水平捲動。
- 新增頁面時把它加進 `NAV_GROUPS`（`js/10b-nav-groups.js`），
  `01-layout` 與 `21-grid-rows` 會自動把它掃進去。
- 畫面裡的 `.sub-tabs` 是**隱藏**的（兩層導覽接手了），但不能刪 ——
  `switchSubTab()` 與 `renderActiveView()` 靠 `.sub-tab.active` 判斷停在哪一個子分頁。

## 4. 可點的東西

- **滑過去一定要有反應。** 量過才算數：`16-interaction` 會把每一種可點元素
  真的用滑鼠移上去，比對 background/border/color/transform/box-shadow/opacity。
  曾經因為方格版面的基底色剛好等於舊的 hover 值，全系統按最多次的那一頁
  滑鼠移過去什麼都沒發生 —— **靜態截圖看不出來**。
- 焦點框用 `box-shadow`，不要用 `outline`：外框會被 `overflow: hidden` 切掉。
  用 `:focus-visible`，不是 `:focus`（滑鼠點一下不該留框）。
- 停用的按鈕要先變灰，不要讓人按了才被拒絕（例如積分不夠時寫「還差 N 點」）。
- 手機的觸控目標至少 ~24px。

## 5. 空狀態

- **整頁空白**（學生端的測驗／兌換／蜂巢分頁）：圖示 + 標題 + 一句
  「什麼時候會出現」。只有一行灰字飄在整片空白上，看起來像壞掉。
- **卡片裡的一段**（積分紀錄、交卷名單）：維持小的那一種，不要放大圖示。
- 空狀態最重要的不是好看，是**告訴使用者下一步該做什麼**
  （「還沒有作業，從上方表單新增一筆」）。

## 6. 圖表

跑過 Claude 的 `dataviz` skill 之後整理出來的，這個專案目前有三處圖表：
班級概況的成長分布、學生端的「這禮拜拿到」、學期成長報表的週長條。

- **先決定形式，顏色最後決定。** 一個數字就是一個數字 —— 不要為了「有圖」畫一根長條。
- **正負一定要用方向，不能只用顏色。** 實測 `--data-pos`／`--data-neg`
  （綠／紅）在紅綠色弱的眼睛裡分離度只有 6.6，安全線是 8。
  所以扣分的長條往**下**長、零線畫成一條髮絲線。
  （深色主題的正值是藍的，那一組六項全過。）
- **圓角只給資料的那一端**，貼著零線的那一端是平的（4px）。
- **不要漸層、不要粗重的飽和色塊**；格線與軸線是比底色深一階的髮絲線，不要虛線。
- **百分比要對著同一個容器算。** 柱子和零線放在不同的框裡（一個含內距、一個不含）
  就會差一個內距的距離 —— 所以兩者都放進 `.report-plot` 那一層。
- **印得出來。** 報表是要印給家長看的，紙上沒有滑鼠：數值不能只放在 hover 的 tooltip。
  （`05-report` 會驗這件事。）
- 刻意不照 dataviz 的一條：數字用的是 serif 的 `--font-display`。
  那是這個專案的識別（守護獸學園是繪本感的），不是裝飾。

顏色要換的時候用驗證器，不要用眼睛判斷：

```bash
node <dataviz skill>/scripts/validate_palette.js "#2e8560,#a8402f" --mode light --surface "#faf7f0"
```

## 7. 文案

- 介面是給**國小老師和小學生**看的：不要出現「同步」「快取」「分片」這種詞。
- 小朋友看得到的地方要講「什麼時候會發生什麼事」，不要只講狀態。
- 老師看得到的地方要講「你現在該做什麼」。
- 所有使用者填的字（姓名、暱稱、加分原因、獎品名稱）**一律 `escapeHtml()`**。
